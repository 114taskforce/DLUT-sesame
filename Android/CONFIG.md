# DLUT 宿舍门禁 —— 完整配置方法（手机 App + ESP32 固件）

一份文档同时覆盖两端：Android App（本仓库 `Android/`）与 ESP32-S3 固件（本仓库 `ESP/`）。
按顺序做完，你会得到：**小爱同学一句话开门 + 校园网自动登录 + 手机随时改配置**。

接口细节（字段表、错误码、云分帧格式）不在这里重复，见 [ESP/docs/app-api.md](../ESP/docs/app-api.md)。本文只讲**怎么配**。

| 组件 | 位置 | 当前版本 |
|---|---|---|
| 手机 App | `Android/`，`com.dlut.dooropener` | 1.4.0 (versionCode 10) |
| 设备固件 | `ESP/`，PlatformIO `env:campusnet` | 协议 `fwVer=1` |

```
手机 App ──局域网 HTTP──▶ ESP32 ──校园网门户认证──▶ auth.dlut.edu.cn
   │                       │  └─ CAS 换票 → menjin.dlut.edu.cn 门禁
   └── MQTT(mqtt.bemfa.com:9501) ──▶ 巴法云 ◀── 米家/小爱同学
        (设备平时也挂在这条长连接上)
```

---

## 0. 先准备这些

1. ESP32-S3 开发板（16MB flash 那款），USB 线，电脑装好 [PlatformIO](https://platformio.org)。
2. 大工统一身份认证账号（学号 + 密码），且该账号在宿主管控系统里**有这把门的权限**。
3. 一个巴法云账号 → <https://cloud.bemfa.com>（免费），只为接小爱同学；不接语音可跳过第 4 步。
4. 手机装了本 App（`app-release.apk` 直接安装，允许"未知来源"）。

## 1. 固件：填出厂默认 → 编译烧录

固件所有出厂值集中在 **`ESP/src/config.h`**，这是唯一需要动的文件：

> **`config.h` 只是出厂默认。** App 同步过的值存在设备的 NVS 里，优先级更高：
> 一旦某项被推送过，之后再改 `config.h` 重新烧录**也不会生效**（代码变了、值没变）。
> 想回到 `config.h` 的值，擦掉 NVS：`pio run -t erase`（会连带清掉已保存的门户地址，
> 需要在设备掉线状态下重连一次）。

| 项 | 填什么 | 说明 |
|---|---|---|
| `CAMPUS_USER` | 学号 | 同时是门禁的 `personId` |
| `CAMPUS_PASS` | 认证密码 | 全项目只有这一处提交账号密码 |
| `COOKIE_INPUT` | 可留空 | 二次认证兜底的浏览器 Cookie。**不用手填**：App「网页登录」抓到的 Cookie 会随第 3 步同步进设备，存在设备 NVS 里 |
| `COOKIE_TRUSTED` | `CASTGC JSESSIONIDCAS` | cookie 白名单：只有这里列的名字会被真正注入会话。改它是因为实测发现把 `devInfo`、`recheck_mobile_error_info` 之类整串灌进去，CAS 就不回带 `lt/execution` 的登录页了 |
| `WIFI_SSID` / `WIFI_PSWD` | `DLUT-LingShui` / `""` | 校园网是开放网络，密码留空 |
| `DOOR_DEVICE_CODE` | 如 `DL-LY-107000` | 宿舍门设备编号；不确定就先填任意值，第 3 步 App 会自动查出来同步过去 |
| `DOOR_PROJECT_CD` / `DOOR_SIGN_SALT` | 不动 | 全校固定值 / 前端硬编码盐 |
| `DEVICE_PIN` | 8~16 位，如 `47124712` | **既是配网热点的 WPA2 密码，也是所有 HTTP/云报文的鉴权口令**，短于 8 位热点开不出来 |
| `BEMFA_KEY` | 巴法控制台首页的"用户私钥" | 留空 = 完全不开云通道 |
| `DOOR_TOPIC` | 如 `Qby0GQH72001` | 控制主题，见第 4 步的命名规则 |
| `CFG_TOPIC` / `ACK_TOPIC` | 任意字母数字，如 `dlutcfg4712` / `dlutack4712` | 远程配置下行 / 回执。不建就只用局域网配 |

引脚和定时间隔在 `ESP/src/main.cpp` 顶部，一般不用改：

| 引脚 | 用途 |
|---|---|
| GPIO0 | 按键：**短按=开门**，长按 1.5s=重新登录刷新，长按 8s=开配网热点 |
| GPIO4 | 外部触发（米家门磁/按钮），上升沿开门，内部下拉，两次间隔 2.4s |
| GPIO48 | WS2812 灯珠 ×3：蓝=登录中、绿闪=成功、黄=token 待重试、红=失败、紫闪=配网热点开着的 |

烧录与看日志：

```bash
cd ESP
pio run -t upload          # 编译并烧到串口
pio device monitor         # 看日志(Ctrl+C 退出)
```

> **不要把 PSRAM 打开。** `platformio.ini` 里刻意不配 `memory_type=qio_opi`：板子的 quad PSRAM 进不了堆，
> 而 mbedTLS 硬件 AES/DMA 一旦把大缓冲分配到 PSRAM 就会堆损坏（`CORRUPT HEAP`，崩在
> `esp_aes_process_dma`）。320KB 内部 RAM 对本项目够用，日志里 `[诊断]` 那行会打空闲堆。

烧完先看串口，正常应当出现：

```
[配置] NVS 载入 N 项, 其余用出厂默认
[云] 目标 mqtt.bemfa.com:9501 控制主题 Qby0GQH72001 配置主题 dlutcfg4712
[WiFi] 已连接: 10.15.x.x
[Cookie种子] 登记 4 条, 用于跳过统一身份认证二次认证      ← 第 3 步之后才有
[云] 巴法云已连接
[云] 主题 Qby0GQH72001 订阅成功(QoS0)
================ 校园网登录结束 ================
[门禁] token: f7b544b9-e4c6-...
就绪: 短按开门 / 长按1.5s刷新 / 长按8s开配网热点 / 门磁触发开门
```

## 2. App：填自己的账号

打开 App → 右上「设置」：

1. **账号 / 密码**：你的学号与统一身份认证密码。
2. **门锁编号**：可以留空 —— 开门和同步时都会自动查（也可以点「自动获取门锁编号」手动选）。
3. **二次认证（信任设备）**：如果开门提示需要短信/验证码，点「打开网页登录」在 App 内完成一次
   带验证码的登录，App 会把 `sso` 与 `menjin` 两个域的 Cookie 存下来（等价固件的 `COOKIE_INPUT`）。
   平时用不到就别管；「清除」等于完整登出。
4. 「自动开门」= 打开 App（或从后台回到前台）就开一次，10 秒内去重；「保留后台」关掉则退出即杀进程。
   这两项是**手机自己**的行为，不会同步给设备。
5. 「使用 WebVPN」= **不在校园网时打开**：校外门禁的会话（token）只存在于浏览器里，所以首次或会话过期后
   要在设置页点一次「打开网页登录」——它会打开 WebVPN 门户，完成登录后自动跳到门禁页并把会话抓进 App；
   之后开门、取门锁编号都经网关。校园网内开着也无妨（App 自动改走直连，少一跳更稳），关掉则完全不碰 VPN。

到这里手机自己已经能开门了。下面才轮到设备。

## 3. 一键同步给设备

1. **长按设备按键 8 秒**（灯紫闪），设备开出热点 `DLUT-Door-xxxx`。
   - 首次上电、NVS 里还没配过 WiFi 时会自动开，不用长按。
   - 热点**不提供外网**：手机连上它之后仍走蜂窝数据，所以你可以一边连设备一边抓 Cookie。
   - 热点密码 = 设备口令（`DEVICE_PIN`，出厂 `47124712`）。
2. 手机连上这个热点，进 App 设置页最下方「同步到门禁设备(ESP32)」，填 **设备口令**。
   设备地址保持默认 `192.168.4.1`。
3. 若要接小爱，展开 **巴法云(小爱同学)**，把私钥和三个主题名填进来。
   （固件 `config.h` 出厂默认留空 = 不开云通道；同步前请填**你自己的**私钥与主题，
   App 填过的值会覆盖固件默认。）
4. 点 **同步到设备**。App 会依次：
   - `GET /status` 先确认设备可达、口令对（避免写到一半才发现连不上）；
   - `POST /save` 推 `user/pass/code/cookie/bemfakey/doortopic/cfgtopic/acktopic`；
     - **空值一律不推**，不会覆盖设备上已有的值；
     - 门锁编号留空时，App 先按账号自动查一次再推；
     - Cookie 只保留 `CASTGC / JSESSIONIDCAS / shfb-token / TGC / route / devInfo` 这几个键
       （设备端上限 480 字节，其余键推过去也没用）。
   - `POST /apply` 让设备立刻用新配置重跑整链认证（最坏几十秒，别关 App）。
5. 点 **试开门**：设备自己发一次开门请求，服务端响应原文会回显到 App —— 这是核对
   "设备编号对不对 / 这个学号有没有权限"最快的办法。点 **读状态** 可看设备当前的
   校园网在线、token 年龄、云连接、空闲堆。

> **注意：设备的 HTTP 服务只在热点开启期间监听**（有意为之：平时不在校园里暴露一个可被扫描的配置口）。
> 所以事后重配也要先长按 8 秒开热点。想长期开放局域网配置，把 `prov.cpp` 里 `sSrv.begin()`
> 从 `provStartAp()` 挪进 `provBegin()` 即可，代价是多一个常开端口。
> 不在现场时改配置，走第 4 步建好的 `CFG_TOPIC`（App 通过云下发，见 [docs/app-api.md](../ESP/docs/app-api.md) 2.2 节）。

## 4. 巴法云 + 小爱同学

**这一步是"为什么查不到设备"的答案所在，请按顺序做。**

1. 登录巴法控制台，记下**用户私钥**（32 位）。
2. **新建三个主题**，协议类型一律选 **MQTT**：
   - 控制主题：名字**只能字母数字、且后三位必须是设备类型码** —— `001` 是插座/开关类，
     例如 `Qby0GQH72001`。不满足这条，主题在米家里根本不会出现。
   - 配置主题、回执主题：名字随意（字母数字），例如 `dlutcfg4712`、`dlutack4712`。
     这两个只给 App↔设备的远程配置用，**没建也能开门**，只是设备日志会打一行
     `主题 xxx 订阅被拒`（这是提示，不是故障）。
3. 服务器地址（实测，别照抄网上教程）：

   | | |
   |---|---|
   | 地址 | `mqtt.bemfa.com:9501`（`bemfa.com:9501` 同集群可用；**`1883` 是关闭的**） |
   | 鉴权 | 标准 MQTT 3.1.1，**ClientID = 用户私钥**，用户名/密码留空 |
   | 订阅 | 只能订**裸主题**。`xxx/set`、`xxx/up` 是发布用的后缀，订阅它们一定被拒（`SUBACK 0x80`） |
   | 心跳 | 60 秒，服务器 65 秒无心跳判掉线 |

4. 把私钥和主题名填进 App（第 3 步第 3 点）→ 同步到设备。设备重启或 `apply` 后，
   串口应打 `主题 Qby0GQH72001 订阅成功(QoS0)`。
5. **绑定米家**：米家 App → 我的 → **其他平台设备** → 添加 → 选「巴法」→ 填巴法账号 →
   设备自动同步进来 → 把它改名成"宿舍门"。
6. 之后就能说：**"小爱同学，打开宿舍门"**。

设备侧收到 `on` → 走和按键完全相同的开门函数 → 把结果上报到 `控制主题/up`
（成功 `on`、失败 `off`，所以米家不会误留"已开"）。若米家里那个开关状态不跟着翻，
把 `ESP/src/cloud.cpp` 里 `handleDoorMsg()` 上报主题的 `%s/up` 改成裸 `%s` 再烧一次。

## 6. 出问题了按这个查

| 现象 | 原因与处理 |
|---|---|
| `[0] 未收到认证跳转` + 没有已保存地址 | 设备当时已在线，拿不到门户入口。等掉线后重启，或让宿管踢下线一次 |
| `[5] 无登录表单` → `[5b] 换票失败: CASTGC 无效或已过期` | 粘过去的 Cookie 过期了。App 重新「网页登录」一次再同步；或把 `COOKIE_INPUT` 清空，让设备走账号密码表单 |
| `[5b] 换票成功` 但 `[10] userOnline 未返回 online=true` | 通常是**账号已在别处在线**（有设备数上限）。到门户里下线其他设备 |
| `[11] 未能解析账户信息` / 余额空白 | 走 CASTGC 直连换票时门户账户接口偶尔取不到 `/eportal/` 会话，**不影响开门**，可忽略 |
| `[门禁] CAS 换票失败` | 校园网没通或 sso 不可达；先解决上一条 |
| `开门失败: 服务端拒绝` | `code`（设备编号）不对、学号无权限、或不在允许时段。用 App「自动获取门锁编号」核对 |
| `连不上设备(192.168.4.1)` | 没长按 8 秒开热点 / 手机没连上该热点 / 口令错（见下条） |
| `设备拒绝:bad-key` | 设备口令填错。口令忘了只能擦 NVS 重来：`pio run -t erase` 后重新配置 |
| `设备拒绝:too-large,字段 cookie 上限 480` | 粘的 Cookie 太长，只保留必要的几个键 |
| `[云] 连接被拒 rc=…` | 巴法私钥错 |
| `[云] 主题 xxx 订阅被拒` | 该主题没在控制台建，或协议类型不是 MQTT。**只影响远程配置，不影响小爱开门** |
| 小爱喊了没反应 | 米家里设备显示离线？看串口 `[云] 巴法云已连接`；宿舍网是否放行 9501 出站（PC 上通不代表宿舍网通），不通就先用局域网那条通道 |
| 灯一直红 | 校园网登录失败，接 `pio device monitor` 看 `[n]` 第几步断的（每步都会打原因） |
| 崩溃/堆损坏类日志 | 检查是否不小心开了 PSRAM（见第 1 步的提示框） |

## 7. 安全提醒

- 账号密码、Cookie 明文存在设备的 NVS 和 App 的私有存储里；**设备离开你身边前请清 NVS**
  （`pio run -t erase`）。
- 设备口令 = 热点密码 = 所有配置接口的鉴权码，**出厂默认 `47124712` 一定要改掉**：
  App 设置页「改设备口令(选填)」里填新口令（≥8 位）再同步一次即可，设备会自动用新密码
  重开热点，手机重连一次就好（App 会记住新口令）。
- 要接云的话，`CFG_TOPIC`/`ACK_TOPIC` 用**够长的随机名**（它等于第二道密钥）：巴法链路是明文
  MQTT，主题名被人拿到 + 口令猜对 = 能改你设备的开门账号。
- 只自用，别拿去影响任何公共门禁设施的正常运行。
